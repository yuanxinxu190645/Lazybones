# AI 资料包

独立于抽取、审核和文献库的本地转换功能。在顶部的 **AI 资料包** 页添加 PDF / DOCX，然后点击“生成 AI 资料包”。不需要配置 AI API，不会自动上传文件。

## 选择模式

- **文本优先**：导出可提取的文字与表格，通常更适合缩小文档附件。图片内容没有包含在 Markdown 中。
- **图文保留**：在文字之外导出每页 PDF 的 PNG 和 Word 正文中的原始图片。适合核对图表、公式和多栏排版，但图片包可能比原文件更大。

扫描 PDF 可勾选 OCR，沿用已有 OCR 的 CPU / GPU 能力。文字稀少、OCR 失败或纯图页会在报告中标记；不能把“转换完成”视作所有信息都已正确识别。

旧版 `.doc` 请先通过 Word / WPS 另存为 `.docx`。此功能不会启动 Office 转换程序，也不会执行宏。

## 输出内容

每次在所选目录下新建一个 `AI资料包_时间_随机编号` 文件夹及同名 ZIP：

- `全文合集.md`：本次成功转换的所有文献，带文献 ID 和 PDF 页码。
- `documents/Dxxxx/全文.md`：每篇的全文。
- `documents/Dxxxx/assets/`：页图、原始图片及公式 OMML 结构（视文档及模式而定）。
- `documents/Dxxxx/tables.json`：识别到的表格结构。
- `parts/`：按预算拆分的文本文件。
- `先读我_质量报告.md`：使用说明、失败文件、OCR 风险及文字不足页码。
- `manifest.json`：来源文件名、SHA-256、分包顺序和转换统计。不包含来源绝对路径字段。
- `分析提示词.txt`：可复制给 AI 的分析任务模板。

完全相同的文件只转换一次，其他文件名以来源记录保留。不会依据 DOI 合并不同版本，也不参与文献库去重。

## 如何发给 AI

文件体积与上下文占用不同。PDF / DOCX 去掉排版后可能很小，但文字量不会因此消失。

1. 先看质量报告，确认失败项、文字不足页码和公式风险。
2. 从“全文合集”“每篇全文”“parts”中选一种上传；它们是相同内容的不同组织方式，不要全部重复上传。
3. 需要分析图表时，另行上传对应图片。Markdown 中的图片链接不意味着目标 AI 已看到图片。
4. 文献过多时分批分析，或放进目标工具支持的检索资料库。同一会话连续发送所有分段，仍可能超出上下文。

token 数为文本估算，不包含图片。分包使用较保守的 UTF-8 字节预算，另留 25% 空间，但仍需以目标模型实际限制为准。超长段落或表格可能跨段；已提取文字不会因为分包而被截断。

ZIP 主要用于存储与搬运。除非目标 AI 明确支持完整解析 ZIP，否则先解压再选择需要的文件。

## 保真与使用边界

不生成摘要，不主动移除参考文献，不使用原抽取流程的最大字数截断。只清理行末空白和过多空行。

这不是无损格式转换：PDF 多栏阅读顺序、复杂表格、OCR 数字与数学符号，以及 Word 的编号、修订、批注、合并单元格和嵌入对象仍可能无法完整还原。Word 公式的简化 LaTeX 应与原文核对，OMML 附件供追溯，并不保证目标 AI 能直接读取。

转换使用单个独立后台进程，逐份处理，界面可以继续操作。停止将在当前处理步骤结束后生效；已完成的结果保留。被中断的任务不得视为完整资料包。正常完成前不会发布最终 ZIP 文件。

本功能不改动原文件和文献库，不自动导入数据库。默认结果位于项目的 `exports/ai_bundles` 子目录，也可选择其他目录。
